## Key facts established by exploration

- **Design 05 is 100% greenfield.** None of the 5 modules exist; no `packages/runtime/src/core/lifecycle/` dir; no `uncaughtException`/`unhandledRejection` handlers anywhere; no shutdown timeout; no auto-restart/supervisor; the IPC `.sock` file is never unlinked on `close()` (orphaned resource).
- Current shutdown (`packages/cli/src/daemon-entry.ts:87-131`): synchronous, idempotent via one boolean, **no timeout**, no resource registry, never calls `runtime.stop()`. `runtime.stop()` (`runtime.ts:218-258`) owns subsystem teardown; `daemon-entry.ts` owns PID/snapshot/IPC/health-server — split-brain.
- Supervisor (`packages/cli/src/daemon.ts`): fire-and-forget after `unref()`; no `exit`/`error` listeners, no restart policy; `stopDaemon` sends only SIGTERM, no escalation/timeout.
- **Reusable building blocks** (from Design 04): `pid-manager.ts` (`isPidAlive`, `isStale`, `cleanupStale`, `validatePid`), `state-store.ts` (snapshots), `health-check.ts` (`checkHealth` + `stalePidFile`). Backoff math pattern at `dispatcher.ts:349`. Worker watchdog pattern at `worker-runtime.ts:252-354`.
- **Template** (from `04_0*`): overview = `# Design 0N — Title — Action Overview` with 6 fixed H2 sections; each action = `# Action NN_MM — Title` with exactly 8 H2 sections (Objective, Backlog reference, Why it matters, Prerequisites, Steps, Files, Constraints, Verification), no H3s, ~70-80 lines, Files use `NEW`/`EDIT`/`READ-ONLY`/`DEPENDS ON` tags, S/M/L sizing in the overview only.
- Build/test: `npm run build` (tsc --build), `npm test` (vitest). New modules re-exported from `packages/runtime/src/index.ts`. INDEX.md does NOT list action docs → no change needed there.
