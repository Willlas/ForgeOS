# Epic 1 — Documentation alignment

> Atomized tasks: [01_documentation-alignment-tasks.md](01_documentation-alignment-tasks.md)

## Objective

Make the top-level documentation honest, coherent, and aligned with the actual repository state.

## User stories

### US-01: README reflects the real project
**As a contributor**
**I want** a single-page overview of Aer that reflects reality
**so that** I can understand the project without reading the whole repository.

**Acceptance criteria:**
- README explains what Aer is in 2–4 lines.
- Main repository structure is listed.
- Current development focus is visible.
- The project is clearly described as pre-MVP.

### US-02: PROJECT_STATE matches the branch reality
**As a project maintainer**
**I want** the project status file to reflect the actual branch and maturity
**so that** status reporting is trustworthy.

**Acceptance criteria:**
- Current branch is named correctly.
- Completed, pending, and planned areas are explicitly separated.
- Outdated status is removed.
- Current sprint objective is visible.

### US-03: ROADMAP is consistent with delivery reality
**As a reviewer**
**I want** a roadmap that matches implemented and planned work
**so that** I can assess the next milestone without contradictions.

**Acceptance criteria:**
- Historical items remain historical and are clearly labeled.
- Current sprints reflect actual progress.
- Sprint 12 is described with realistic scope.
- Aspirational work is clearly separated from short-term scope.

## Tasks

- Review existing README and rewrite it in a factual style.
- Review PROJECT_STATE and validate the current branch and maturity notes.
- Review ROADMAP and adjust the classification of completed/planned work.
- Confirm the sprint milestone documentation aligns with the active branch.
