### Task 2 (S14-E5.2): Serialization guard
Add an explicit serialization-leak guard that fails any CLI validation run when command output contains `[object Object]` or `[Symbol(`.

## Objective
Prevent IPC error serialization from silently producing unreadable operator output across the CLI command surface.

## Target files
- Extend or create: `packages/cli/src/__tests__/cli-malformed-input.test.ts`
- Reuse: `packages/cli/src/__tests__/helpers/cli-harness.ts`
- Reference: `packages/cli/src/index.ts`

## Subtasks

### Subtask 2A: Add a cross-command leak assertion
- Add a shared assertion that combines `stdout` and `stderr` from each CLI invocation.
- Fail the test when the combined output contains `[object Object]` or `[Symbol(`.
- Keep the assertion reusable across the smoke-test command set.

### Subtask 2B: Add the daemon-down leak assertion
- Execute at least one daemon-down workspace command through the E1 harness.
- Assert exit code `1`.
- Assert the command output does not contain `[object Object]` or `[Symbol(`.

### Subtask 2C: Add the malformed-input leak assertion
- Reuse the same assertion for all E5.1 malformed-input rows.
- Confirm that each failure remains human-readable.

### Subtask 2D: Add the provider-status leak assertion
- Execute the provider status path through the E1 harness.
- Assert that the output remains readable when the provider is unreachable.
- Confirm that the command still exits with code `0`.

### Subtask 2E: Keep the guard focused
- Do not modify production serialization or IPC output formatting.
- Do not replace the existing E2 failure-description behavior.
- Do not add test-only production hooks.
