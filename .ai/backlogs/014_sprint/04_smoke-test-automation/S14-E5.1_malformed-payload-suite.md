### Task 1 (S14-E5.1): Malformed payload suite
Create a deterministic CLI malformed-input suite that covers the validation paths owned by S14-E5.1 and excludes approval-lifecycle, daemon-status, and serialization assertions.

## Objective
Prove that malformed CLI payloads fail with a stable exit code, clear stderr output, and no `[object Object]` leakage.

## Target files
- New: `packages/cli/src/__tests__/cli-malformed-input.test.ts`
- Reuse: `packages/cli/src/__tests__/helpers/cli-harness.ts`
- Reference: `packages/cli/src/index.ts` for argument validation

## Subtasks

### Subtask 1A: Add the malformed preview test
- Use the E1 harness to invoke `workspace:preview` with a missing required option or invalid argument combination.
- Assert exit code `1`.
- Assert stderr contains a clear validation message identifying the missing or invalid argument.
- Assert `assertNoObjectLeak(result)`.

### Subtask 1B: Add the malformed approve test
- Invoke `workspace:approve` without the required `diffHash` or with an invalid argument shape.
- Assert exit code `1`.
- Assert stderr contains the exact validation message produced by the current CLI implementation.
- Assert `assertNoObjectLeak(result)`.

### Subtask 1C: Add the malformed apply test
- Invoke `workspace:apply` with a missing or invalid file/content pair.
- Assert exit code `1`.
- Assert stderr contains the exact validation message produced by the current CLI implementation.
- Assert `assertNoObjectLeak(result)`.

### Subtask 1D: Add the malformed TTL test
- Invoke `workspace:approve` with `--ttl 0` or another invalid TTL value.
- Assert exit code `1`.
- Assert stderr contains the exact validation message produced by the current CLI implementation.
- Assert `assertNoObjectLeak(result)`.

### Subtask 1E: Keep the test scope bounded
- Cover only malformed argument and payload validation.
- Do not duplicate the approval-lifecycle assertions from S14-E3.
- Do not duplicate daemon-down assertions from S14-E4.3.
- Do not assert provider behavior.
