### Task 1 (S14-E6.1): Formal operator runbook
Create a permanent, executable operator runbook for the Sprint 14 CLI validation and hardening path.

## Objective
Document the exact commands, expected exit codes, expected stdout or stderr content, and recovery steps for every operator-facing scenario covered by Sprint 14.

- New or replace: `docs/cli-operator-test-plan.md`
- Reference: `.ai/backlogs/014_sprint/README.md`

## Subtasks

### Subtask 1A: Add the quick-start section
- Add commands for starting the daemon and checking status.
- Add the command to run the automated smoke suite: `npm run smoke:cli`.
- Document that the smoke suite does not require a live Ollama provider.

### Subtask 1B: Document the happy path
- Document the exact sequence:
  - `aer status`
  - `aer workspace:grant`
  - `aer workspace:preview`
  - `aer workspace:approve`
  - `aer workspace:apply`
- Record the expected success exit code and the output signals that indicate success.
- Document how to capture `diffHash` and `approvalId` from the command output.

### Subtask 1C: Document failure-path commands
- Duplicate `approvalId`.
- Read-only grant misuse.
- Malformed arguments or payloads.
- Daemon down.
- Provider unreachable.
- Include the exact expected exit code and stderr string for each row.

### Subtask 1D: Document recovery checks
- Restart the daemon.
- Re-register the grant.
- Repeat the happy path.
- Confirm that cross-session or cross-root behavior remains rejected.

### Subtask 1E: Keep the runbook evidence-based
- Base every expected result on the corresponding automated test.
- Do not describe behavior that has not been verified by the Sprint 14 test suite.
- Link the runbook to the relevant smoke-test and unit-test files where applicable.
