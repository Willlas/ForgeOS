# S14-E3.1: Runtime approval-lifecycle suite (in-process)

## Task
Create a new in-process test suite `packages/runtime/src/__tests__/approval-lifecycle.test.ts` that locks the **preview → approve → apply** contract at the runtime boundary — no daemon, no IPC pipes, no file-IO harness. It calls the `Runtime` approve/apply methods directly and pins the four invariants (single-use consumption, session + rootPath binding, TTL default/clamp, diffHash binding) with exact error strings. It complements the existing `workspace-tools.test.ts` (raw `WorkspaceTools` mechanics) and `session-grant-manager.test.ts` (grant registration) — those stay untouched; this suite exercises the **runtime approval record** (`runtime.ts:169`) end-to-end.

## Target
- **New:** `packages/runtime/src/__tests__/approval-lifecycle.test.ts`

## Acceptance criteria
1. **Single-use (headline):** `preview → approve → apply` succeeds (`applied === true`, target file content present) → apply again with the same `approvalId` → throws `"Unknown or already-consumed approvalId"` (`runtime.ts:534`) and the file content is unchanged.
2. **Session binding:** approval approved in session A → apply attempted in session B → throws `"Approval belongs to a different session"` (`runtime.ts:537`).
3. **rootPath binding:** apply with a different `rootPath` than the one approved → throws `"Approval rootPath does not match the requested rootPath"` (`runtime.ts:540`).
4. **TTL default & clamp:** approve with no `expiresInSeconds` → `expiresAt − createdAt === 300_000 ms`; approve with `expiresInSeconds: 7200` → `expiresAt − createdAt ≤ 3_600_000 ms` (pins the `runtime.ts:171-172` contract).
5. **Expiry:** approval with a 1-second TTL, wait ~1.1s → apply → throws `"Approval has expired"` (`runtime.ts:544`).
6. **diffHash binding:** approve diff A → apply a *different* change set whose computed diffHash B ≠ A → throws `"Approval diffHash does not match the requested change set"` (`workspace-tools.ts:435`) and no file is written.
7. **Guard rails:** `approve` without a `diffHash` → `"Approve requires a non-empty diffHash from a prior preview"` (`runtime.ts:499`); a read-write grant registered *without* `approvalRequired` → both `preview` and `approve` reject with `"Workspace tool 'apply' is not granted"` (`runtime.ts:470,496`).
8. **Audit safety:** the `approve` response carries no `approvalToken` — assert `Object.keys(approval).not.toContain("approvalToken")` (pins `ipc-protocol.ts:364`).
9. **Suite hygiene:** no daemon, no pipes, no network; temp roots cleaned in `afterAll`.

## Approach
- **Setup (mirror `workspace-tools.test.ts` + `session-grant-manager.test.ts`):**
  - Track temp roots (`mkdtemp(path.join(os.tmpdir(), "aer-approval-"))`) in `temporaryRoots: string[]`; `afterAll` removes each with `rm(root, { recursive: true, force: true }).catch(() => {})`.
  - **Singleton isolation (critical):** `createRuntime()` binds the module singleton `getSessionGrantManager()` **at construction time** (`runtime.ts:196`), so `resetSessionGrantManager()` does *not* re-point an already-constructed `Runtime` (the constructor is clean — no resources to tear down, only `config`/`state`/`selfLogger`). Therefore **instantiate a fresh `Runtime` inside each `it`** and run `afterEach(() => resetSessionGrantManager())`. That way the `Runtime` and the grant helper always observe the same fresh singleton (relies on `resetSessionGrantManager()` behaving as `session-grant-manager.test.ts` already assumes).
  - **Grant helper** — register a read-write `apply` grant through the same public registry the `Runtime` reads:
    ```ts
    function grantApply(rootPath: string, sessionId: string) {
      getSessionGrantManager().registerGrant(sessionId, {
        rootPath,
        mode: "read-write",
        tools: ["apply", "read", "list", "search"],
        approvalRequired: true,
      });
    }
    ```
  - **Call shapes** (from `runtime.ts` + `ipc-protocol.ts`):
    - `preview(rootPath, { sessionId, changes })` → `{ diffHash, files: [{ relativePath, expectedHash, size }] }` (`runtime.ts:465-517`, `workspace-tools.ts:156`).
    - `approve(rootPath, { sessionId, diffHash, expiresInSeconds? })` → `{ approvalId: "wsa_…", sessionId, grantId, rootPath, diffHash, createdAt, expiresAt }` (`runtime.ts:512-519`; `approvalId` = `wsa_${sessionId.slice(0,8)}_${ts}_${n}`, `runtime.ts:508`).
    - `apply(rootPath, { sessionId, approvalId, changes })` → `{ rootPath, applied: true, rolledBack: false, restored: [], files: [{ relativePath, previousHash, newHash }], diffHash }`.
    - `changes` items: `{ relativePath, content, expectedHash? }` (`ipc-protocol.ts:348-352`).
  - **Reference:** `workspace-tools.test.ts` (temp-root cleanup, `expectedHash`), `session-grant-manager.test.ts` (registration + `resetSessionGrantManager`).

## Notes
- **Create the `Runtime` fresh per test** (inside each `it`) — never at module scope — because `resetSessionGrantManager()` orphans an already-constructed instance's grant-manager reference.
- **TTL assertions are millisecond-exact:** `new Date(expiresAt).getTime() - new Date(createdAt).getTime()` equals `ttl * 1000`; for the clamp case use `≤ 3_600_000` (the `min` clamp at `runtime.ts:503`).
- **Expiry uses real time** (~1.1s wait on a 1s TTL) — consistent with the `setTimeout`-based expiry test in `session-grant-manager.test.ts` and well inside the E1.2 30s budget; no fake timers needed.
- **diffHash mismatch:** the guard fires at apply time (`workspace-tools.ts:435`), so approve diff A then apply a change set with different `relativePath`/`content` (e.g. an extra file) to force a different diffHash.
- Keep error strings **verbatim**; if the E2 message-routing change rewords any, this suite fails loudly — re-read `runtime.ts:499,534,537,540,544` and `workspace-tools.ts:435` before asserting.
